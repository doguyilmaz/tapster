In tapster setup, open **Projects**.

<Image src={projects} alt="The Projects page lists the clones of your repositories on this computer, with their kind and an Add button." />

tapster looks for clones of your own repositories in the folder you started it from, its parent and the usual places
such as `~/Developer`, `~/Projects` and `~/code`. It reads each clone's `.git/config` and checks which build files
exist. Nothing leaves your computer. If a project lives elsewhere, type its folder and click **Look there too**.

It recognizes three kinds of projects:

- **Go with GoReleaser**: a `.goreleaser.yaml` next to `go.mod`. See [Move a GoReleaser project](/guides/goreleaser/).
- **Bun**: a `package.json` with `bin` and a `bun.lock`. See [Bun projects](/guides/bun/).
- **A Mac app with Sparkle**: see [Mac apps with Sparkle](/guides/sparkle/), which has its own order of steps.

## 1. Choose the options

Click **Add** next to the project.

<Image src={project} alt="The project sheet shows the kind, branch and protection of the project, its options and what tapster will do." />

The sheet shows what tapster found and what it will do. The options:

- **The workflow that runs GoReleaser**, when a Go project has more than one.
- **Let the release workflow push tags**, for workflows that tag by themselves. See
  [Releases tagged by a workflow](/guides/auto-tag/).
- **Keep Dependabot's pull requests**, preselected when the project uses Dependabot. See [Dependabot](/guides/dependabot/).
- **Replace the existing release workflow**, when a Bun project or app already has one tapster does not recognize.

Click **Add to you/homebrew-tap**. tapster then:

- edits the release workflow so it opens a draft, attests the archives and rings the hub;
- protects the project: only you can create, move or delete its branches and tags. A stolen App key cannot tag code for
  your hub to sign. Your own pushes show "Bypassed rule violations", which is your admin right at work;
- opens a pull request on the hub with the project's entry for `tapster.yml`.

## 2. Commit, merge and install

<Image src={added} alt="After adding, the sheet shows the changes as a diff and the next steps: commit, push, merge the hub entry and install the App." />

<Steps>

1. Review the diff, then click **Commit these files** and **Push**. tapster commits only the files it changed, with your
   own git setup, so your hooks and commit signing apply. If git needs a password, the page gives you the command to run
   in a terminal.
2. Click **Review and merge on GitHub** and merge the pull request on the hub.
3. Click **Install the App** unless the App already reaches this project. GitHub preselects it; keep
   **Only select repositories**.

</Steps>

If the repository's GitHub description is one that Homebrew would reject, the sheet says so and the entry suggests a
better one. Homebrew wants a short description that starts with a capital letter and has no full stop at the end.

:::note
A project whose archive names tapster cannot predict yet, for example GoReleaser with its own name template, gets no
entry until its first draft exists. Add it again after that.
:::

:::note[Where your keys go]{icon="padlock"}
The project holds no keys. If it still has old release secrets such as `MACOS_*` or `HOMEBREW_TAP_*`, the sheet lists
them. Delete them once the hub has published a release.
:::
